# frontend/common

Code the frontend shares with other Penpot services — currently the headless
exporter. One subtree so far:

## `app.render-wasm-common.*`

The host-agnostic ClojureScript side of the render-wasm binary protocol: the
byte layouts, memory helpers and serializers that turn Penpot shapes into the
buffers `render-wasm` consumes, plus the google fonts catalog both hosts
resolve through (`app.render-wasm-common.gfonts`).

The workspace drives it from `app.render-wasm.*`, the exporter from
`app.wasm.*` / `app.renderer.wasm` — same code underneath, so a second
implementation cannot drift from the first.

It does not live under `render-wasm/` because that tree is Rust and WASM only,
but the layouts here and the Rust that defines them must still change together.

`src/app/render_wasm_common/api/shared.js` is generated by `render-wasm/build`
(`copy_shared_artifact` in `render-wasm/_build_env`) and is not committed.

## Rules for anything added here

This is a module, not part of the frontend app. **Nothing here may depend on a
browser (no DOM, no WebGL, no app state) or on `frontend/src`.** Host concerns
such as the canvas, the GL context and the fonts DB stay in their respective
callers. Dependencies are `app.common.*` and this module's own namespaces only.

That is enforced, not just documented: the exporter puts this module on its
classpath *without* `frontend/src`, so a stray `app.main.*` require fails its
build. It also has to keep running under plain Node — a `js/document` here
breaks the exporter, not just a test.
